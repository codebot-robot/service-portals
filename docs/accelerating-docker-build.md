# Accelerating Docker Builds with Artifact Caching Proxy

Building Docker images that include Python dependencies (`pip install -r requirements.txt`) can be a significant bottleneck during development and CI/CD pipelines. Downloading the same packages repeatedly wastes time and bandwidth.

The **Artifact Caching Proxy (Artifact Portal)** is a dedicated caching HTTP/HTTPS forward proxy designed specifically to accelerate these package download operations.

---

## How It Works

By routing your Docker build's network traffic through the Artifact Portal:
1. When `pip` requests a package (e.g., a `.whl` or `.tar.gz` from PyPI), the proxy intercepts the request.
2. If the package is already cached in the local `./cache` directory, the proxy immediately serves it from disk.
3. If the package is not cached, the proxy fetches it from the upstream repository, caches it on disk, and returns it to `pip`.
4. Since PyPI is served over HTTPS, the proxy uses **Man-In-The-Middle (MITM)** decryption/encryption (utilizing an automatically generated self-signed Root CA) to securely inspect and cache HTTPS `GET` requests.

---

## 1. Running the Artifact Caching Proxy

You can run the Artifact Caching Proxy directly from the source code or as a Docker container.

### Running from Source
Run the proxy from the repository root:
```bash
go run cmd/artifact-portal/main.go
```

When started with no environment variables, the proxy will:
* Automatically generate a self-signed Root CA at `./certs/ca.crt` and `./certs/ca.key` (if they do not already exist).
* Create a persistent cache directory at `./cache`.
* Start listening on port `8080` (HTTP forward proxy) and `8443` (HTTPS MITM forward proxy).
* Use a default cache TTL of `24h` (24 hours).

### Running via Docker
If you want to run the proxy as a Docker container on your host machine:
```bash
# 1. Build the artifact-portal image (if not already built)
docker build -t gke-labs/artifact-portal -f - <<EOF
FROM golang:1.24-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o /artifact-portal cmd/artifact-portal/main.go

FROM alpine:latest
COPY --from=builder /artifact-portal /artifact-portal
EXPOSE 8080 8443
ENTRYPOINT ["/artifact-portal"]
EOF

# 2. Run the proxy with volumes mounted for CA certs and cache persistence
docker run -d \
  --name artifact-portal \
  -p 8080:8080 \
  -p 8443:8443 \
  -v $(pwd)/cache:/cache \
  -v $(pwd)/certs:/certs \
  -e CACHE_DIR=/cache \
  -e CA_CERT_PATH=/certs/ca.crt \
  -e CA_KEY_PATH=/certs/ca.key \
  gke-labs/artifact-portal
```

## 2. Configuring Your Dockerfile

Because PyPI packages are downloaded over HTTPS, the `pip` command inside the Docker build container must trust the dynamically generated Root CA certificate from the proxy.

The cleanest way to do this without permanently baking the proxy CA into your production image is to use the `PIP_CERT` environment variable during the build stage.

Here is an example `Dockerfile`:

```dockerfile
# syntax=docker/dockerfile:1
FROM python:3.11-slim

WORKDIR /app

# 1. Declare build arguments for proxies
ARG http_proxy
ARG https_proxy

# 2. Copy the CA certificate generated by the proxy into a temporary location.
#    This file is generated in the host's `./certs/ca.crt`.
COPY certs/ca.crt /tmp/ca.crt

# 3. Configure pip to use the CA certificate for validation during build
ENV PIP_CERT=/tmp/ca.crt

# 4. Copy and install requirements. 
#    These requests will automatically route through the proxy build arguments.
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 5. Clean up the certificate so it's not present in the final image
RUN rm -f /tmp/ca.crt
ENV PIP_CERT=

# Copy application files
COPY . .

CMD ["python", "main.py"]
```

## 3. Running the Docker Build

To run the build and route traffic through the caching proxy, pass the `http_proxy` and `https_proxy` build arguments pointing to the proxy.

### On Linux
On Linux hosts, you can map `host.docker.internal` to the host's gateway IP using `--add-host`:

```bash
docker build \
  --build-arg http_proxy=http://host.docker.internal:8080 \
  --build-arg https_proxy=http://host.docker.internal:8443 \
  --add-host=host.docker.internal:host-gateway \
  -t my-python-app .
```

### On macOS / Windows
On macOS and Windows, `host.docker.internal` is resolved automatically by Docker Desktop, so you only need to pass the build arguments:

```bash
docker build \
  --build-arg http_proxy=http://host.docker.internal:8080 \
  --build-arg https_proxy=http://host.docker.internal:8443 \
  -t my-python-app .
```

## Environment Variables Configuration

You can customize the proxy's behavior using the following environment variables:

| Environment Variable | Default Value | Description |
| :--- | :--- | :--- |
| `PORT` | `8080` | Port for the HTTP proxy |
| `HTTPS_PORT` | `8443` | Port for the HTTPS MITM proxy |
| `CACHE_DIR` | `./cache` | Directory where cached artifacts are stored |
| `CACHE_TTL` | `24h` | Time to live for cached artifacts (e.g. `24h`, `168h`) |
| `CA_CERT_PATH` | `./certs/ca.crt` | Path to the CA certificate |
| `CA_KEY_PATH` | `./certs/ca.key` | Path to the CA private key |
